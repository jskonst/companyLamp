# План 12 — Архитектурная Стабилизация

## Цель
Стабилизировать базовую архитектуру перед дальнейшим функциональным ростом:
- убрать критичные технические риски в runtime,
- синхронизировать состояние UI и режима работы,
- зафиксировать чистую структуру исходников и минимальный smoke-контур.

План не добавляет новый пользовательский функционал. Это план надежности и предсказуемости системы.

---

## 12.1 Критические Исправления

### 12.1.1 MQTT host lifetime
Проблема:
- в `mqtt.setServer(cfg::host().c_str(), cfg::port())` используется `c_str()` временного `String`.
- это риск dangling pointer и нестабильного переподключения MQTT.

Требование:
- хранить host в стабильном буфере/переменной с жизненным циклом дольше вызовов `mqtt.loop()`.
- вызывать `setServer()` только с валидным стабильным указателем.

### 12.1.2 Единый источник истины для DND в UI
Проблема:
- в UI переключатель DND может менять только `kk::dnd`, но активный режим определяется `kk::mode`.
- это создает рассинхрон между экраном и фактическим рендером.

Требование:
- переключение DND из web должно вызывать ту же бизнес-логику, что и кнопка (`toggleDND()` или эквивалентный единый хелпер).
- `kk::dnd` и `kk::mode` всегда согласованы.

---

## 12.2 Гигиена Исходников

### 12.2.1 Удалить автоген из `src/`
Проблема:
- файл `src/WebLamp_v1.0.ino.cpp` — автоген/preprocessed артефакт, не исходник проекта.
- наличие такого файла в `src` повышает риск двойной компиляции и расхождения с реальными `*.ino`.

Требование:
- убрать `src/WebLamp_v1.0.ino.cpp` из репозитория.
- добавить правило в `.gitignore`, чтобы этот артефакт больше не попадал в git.

### 12.2.2 Явные границы модулей
Требование:
- минимизировать прямые cross-module вызовы без контракта.
- все общие операции состояния (power/mode/dnd) держать в одном слое (`mode.*` / отдельный state-controller).

---

## 12.3 Минимальный Smoke-Контур

Добавить короткий регламент ручной проверки (README/FEATURES):
1. Boot без WiFi -> AP поднят, web доступен.
2. Подключение к WiFi -> получение IP, MQTT reconnect стабилен.
3. `1 клик` в каждом режиме -> одинаковый power toggle.
4. DND: кнопка и web переключатель дают одинаковое состояние/индикатор.
5. Смена режима (кнопка и web tabs) не оставляет "висящую" индикацию.

## 12.5 Критерии Приемки

- [ ] MQTT подключается/переподключается без случайных отвалов из-за host pointer lifetime.
- [ ] Переключение DND из web и кнопкой дает одинаковый результат и в UI, и в рендере.
- [ ] В `src/` отсутствуют автоген-файлы вида `*.ino.cpp`.
- [ ] Документация соответствует реальному поведению кнопки и режимов.
- [ ] Есть короткий smoke-checklist для быстрой регресс-проверки после изменений.
