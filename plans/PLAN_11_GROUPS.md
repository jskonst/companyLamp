# План 11 — Управление группами

## Цель
Добавить поддержку нескольких групп ламп с переключением между ними.
Сейчас лампа работает в одной группе (план 06). Этот план расширяет систему
до N групп с удобным UI.

> **Предусловие:** PLAN_06 реализован. Одна группа (`cfg::group()`) уже работает.

---

## 11.1 Модель данных

Вместо одного поля `kk::group` — массив профилей групп.

```cpp
struct GroupProfile {
  char name[20];     // отображаемое имя, например "Работа"
  char topic[20];    // MQTT-идентификатор, например "office"
};
```

Хранение: в DB как JSON-строка или как набор ключей `group0_name`, `group0_topic`, ...
Активная группа: `kk::active_group` (индекс 0–N).

---

## 11.2 UI — страница групп

Отдельная секция в веб-интерфейсе (или отдельная страница через GyverHTTP).

- Список групп: имя + топик + кнопка «удалить»
- Форма добавления: поле «Имя» + поле «Топик»
- Кнопка «Активировать» рядом с каждой группой
- Текущая активная группа выделена

---

## 11.3 Переключение группы

При смене активной группы:
1. Отписаться от `GWL/<old_group>/+/#`
2. Сбросить `remotes[]` (все удалённые лампы из старой группы)
3. Подписаться на `GWL/<new_group>/+/#`

```cpp
void switchGroup(uint8_t idx) {
  if (!mqtt.connected()) return;
  String oldTopic = String("GWL/") + cfg::group() + "/+/#";
  mqtt.unsubscribe(oldTopic.c_str());

  remoteCount = 0;  // сброс списка удалённых ламп

  cfg::setActiveGroup(idx);

  String newTopic = String("GWL/") + cfg::group() + "/+/#";
  mqtt.subscribe(newTopic.c_str());
}
```
