# План 03c — Рефакторинг startup.ino

## Цель
Сократить и структурировать `src/startup.ino`, сохранив текущее поведение 1:1:
- те же тайминги,
- те же переходы состояний,
- те же визуальные сигналы.

Задача плана — улучшить читаемость, поддержку и расширяемость, без функциональных изменений.

---

## 03c.1 Проблема

Сейчас `startup.ino` выполняет слишком много ролей в одном месте:
- инициализация железа,
- логика переходов между фазами старта,
- AP-ветка,
- анимации и эффекты,
- финализация состояния лампы.

Из-за этого трудно:
- безопасно менять этапы старта,
- отлаживать проблемы подключения,
- переиспользовать/тестировать отдельные части.

---

## 03c.2 Архитектурная цель

Разделить startup-код на:
1. **Оркестрацию** (переходы между фазами),
2. **Анимации** (визуальные хелперы),
3. **Служебные утилиты** (кнопка, финализация, логи).

---

## 03c.3 Декомпозиция функций

### Оркестрация

```cpp
void startup();
static void startupInitHardware();
static bool startupWarmupWindow();        // true -> перейти в AP
static bool startupTryWifiConnect();      // true -> connected
static void startupRunApMode();           // блокирует до restart/выхода
static void startupFinalize();
```

### Анимации

```cpp
static void startupShowBlack();
static void showWifiWaitPulse();
static void showWifiConnectedBlink();
```

### Утилиты

```cpp
static bool startupButtonClicked();
static void startupLogState(const __FlashStringHelper* tag);
```

---

## 03c.4 Явные фазы старта (state machine)

Ввести enum для читаемого flow:

```cpp
enum class StartupState : uint8_t {
  INIT,
  WARMUP,
  WIFI_CONNECT,
  AP_MODE,
  FINALIZE,
  DONE
};
```

`startup()` управляет переходами между фазами.

Плюсы:
- проще читать и дебажить,
- меньше скрытых переходов `return` из середины функции,
- легче добавлять новые ветки (например, fallback-политики).

---

## 03c.5 Константы и группировка параметров

Сгруппировать все startup-тайминги и яркости в один блок:

```cpp
// startup timing
constexpr uint32_t STARTUP_BOOT_DELAY_MS = ...;
constexpr uint32_t STARTUP_WARMUP_MS = ...;
constexpr uint32_t STARTUP_WIFI_TIMEOUT_MS = ...;

// startup animation
constexpr uint8_t  STARTUP_WIFI_WAIT_BRIGHT_MIN = ...;
...
```

Цель: убрать «магические числа» из тела функций.

---

## 03c.6 Контракт AP-ветки

Сделать AP-ветку самостоятельной и предсказуемой:
- запуск AP,
- синий breathing,
- обработка кнопки (выход/перезапуск),
- явный выходной результат (например, enum reason).

Это снизит связность с остальным startup-кодом.

---

## 03c.7 Логирование этапов

Добавить стабильные метки логов:

```cpp
[STARTUP] INIT
[STARTUP] WARMUP
[STARTUP] WIFI_CONNECT
[STARTUP] AP_MODE
[STARTUP] FINALIZE
[STARTUP] DONE
```

Это упростит диагностику «зависли на каком этапе».

---

## 03c.8 Ограничения (важно)

- Не менять текущую логику переходов и условия.
- Не менять UX анимаций (это уже покрыто планами 03/03b).
- Не менять MQTT/режимы/кнопку вне startup-сценария.
