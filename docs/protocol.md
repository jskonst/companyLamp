# Протокол группы ламп (MQTT)

Группа из 2–20 ламп на своём брокере Mosquitto (см. `infra/broker/`).
Документ описывает топики и payload прошивки ветки `refactor` и статус/LWT,
которые перенос на `main` добавляет сверху. Префикс `lamp/` в пути топика —
обязательное изменение прошивки, см. [Решение для прошивки](#решение-для-прошивки).

## Идентификация

- `group` — имя группы из портала: латиница, цифры, `-`, до 20 символов. По умолчанию `office`.
- `id` — идентификатор лампы в пути топика. В текущем `refactor` это поле `local` из портала (по умолчанию `lamp_1`). Перенос на `main` заменяет его на `ESP.getChipId()` в hex, 6 символов, например `a1b2c3`; вручную не задаётся. Имя в портале, если останется, только для отображения.
- В портале также задаются хост и порт брокера, логин и пароль.
- MQTT client id после переноса: `lamp-<id>`, clean session, keepalive 15 с. В текущем `refactor` клиент подключается как `WebLamp-<случайный hex>`, без Last Will; keepalive библиотеки — те же 15 с.

## Топики

Целевой путь (после исправления прошивки): `lamp/<group>/<id>/<subtopic>`.

В текущем `refactor` префикса `lamp/` нет, путь выглядит как `<group>/<local>/<subtopic>` — такой вариант **не проходит ACL брокера**.

| Топик | Retained | QoS | Содержимое | Откуда |
|---|---|---|---|---|
| `lamp/<group>/<id>/status` | да | 1 | `online`, `away` или `offline` | добавляет перенос |
| `lamp/<group>/<id>/heartbeat` | да | 0 | `0` или `1` (PIR) | `refactor` |
| `lamp/<group>/<id>/mood` | да | 0 | число `0`…`120` | `refactor` |
| `lamp/<group>/<id>/dnd` | да | 0 | `0` или `1` | `refactor` |
| `lamp/<group>/<id>/pomodoro` | да | 0 | `work:<color>`, `break` или `idle` | `refactor` |
| `lamp/<group>/<id>/meeting` | нет | 0 | имя или `id` отправителя | `refactor` |

QoS 0 у топиков `refactor` — фактическое поведение `PubSubClient` (двух- и трёхаргументный `publish` / `subscribe` без QoS). `status` публикуется с QoS 1, как в текущем `main`.

Лампа подписана на `lamp/<group>/+/#` (сейчас в коде: `<group>/+/#`). Сообщения со своим `id` игнорирует. Чужие лампы появляются в списке при первом любом сообщении; до 20 записей (`MAX_REMOTE_LAMPS`).

### status (добавляет перенос)

В `refactor` отдельного топика статуса нет: «в сети» определяется по `heartbeat` (таймаут 18 с). Перенос добавляет явный статус и Last Will, чтобы обрыв питания или Wi-Fi был виден группе без ожидания пропущенных heartbeat.

- При подключении задаётся Last Will: `offline`, retained, QoS 1. Если лампу выдернули из розетки или пропал Wi-Fi, брокер сам опубликует `offline` примерно через 1,5 keepalive (около 22 с).
- Сразу после подключения лампа публикует `online`, retained, QoS 1.
- При входе в офлайн-режим лампа публикует `away`, retained, QoS 1, и отключается штатно (чтобы LWT не затёр `away` словом `offline`).

После переноса источник правды для присутствия — `status`. `heartbeat` остаётся для PIR и как запасной признак жизни: если `status` ещё не приходил, лампа считается онлайн при heartbeat младше 18 с.

### heartbeat

Публикуется каждые 8 с, retained. Payload: `1`, если PIR активен, иначе `0`. Сейчас `USE_PIR` выключен, поэтому обычно уходит `0`. Отдельного топика `pir` в коде нет.

### mood

Настроение владельца — целое число от 0 (плохо, красный) до 120 (хорошо, зелёный). Публикуется строкой, например `120`. Отправляется двойным кликом в режиме «Настроение», если есть связь и не включён офлайн-режим. Хранится в локальной БД; ключ `mood_date` в прошивке есть, но ежедневный сброс не реализован.

### dnd

`1` — «не беспокоить» включён, `0` — выключен. Публикуется при входе и выходе из DND (4 клика или переключатель в портале). Рабочий интервал Pomodoro тоже ставит `dnd=1`, перерыв и завершение — `dnd=0`.

Входящее `dnd` запоминается у удалённой лампы. Входящий `pomodoro`, который начинается с `work`, тоже ставит ей `dnd=true`.

### pomodoro

Состояние таймера, retained:

- `work:<color>` — начался рабочий интервал; `<color>` — настроенный рабочий цвет, оттенок FastLED 0–255, десятичная строка (например `work:0`).
- `break` — короткий или длинный перерыв.
- `idle` — интервал завершён (состояние `DONE`).

Пауза и продолжение по MQTT не публикуются. Вместе с `work:…` уходит `dnd=1`, вместе с `break` и `idle` — `dnd=0`.

### meeting (wink)

Подмигивание группе по 5 и более кликам. Не режим, а разовое действие. Payload в текущем коде — `cfg::local()` (имя лампы). После перехода на chip id в пути топика отправителя надёжнее брать из самого топика; payload может остаться отображаемым именем.

Получатели делают локальную вспышку текущим цветом, если в настройках включено «Принимать wink-сигналы» (`dnd_wink`, по умолчанию да). Сам режим DND вспышку автоматически не глушит — только этот переключатель.

## Среднее настроение группы

В режиме «Настроение» кольцо показывает среднее, а не только своё значение.

```
avg = (своё mood + сумма mood онлайн-коллег) / (1 + число онлайн-коллег)
```

Деление целочисленное. Своя лампа всегда входит в среднее. Коллега учитывается, только если он онлайн: после переноса при `status=online`, до появления `status` — если heartbeat был меньше 18 с назад. `away` и `offline` не входят в среднее.

Усредняется число `mood` (0–120), а не оттенок по кругу, поэтому красный и зелёный дают жёлтый, а не синий. Для ленты число переводится в оттенок FastLED HSV:

```
hue = map(constrain(mood, 0, 120), 0, 120, 0, 85)
```

`0` — красный, `85` — зелёный (около 120° обычного HSV).

## Офлайн-режим

Включается переключателем в портале (`offline`). Локально работают лампа, Pomodoro, личное настроение и визуальный DND.

В текущем `refactor` лампа просто перестаёт вызывать MQTT: не подключается, не шлёт heartbeat и не публикует состояние. Перенос должен перед отключением опубликовать `status=away` и закрыть сессию штатно. В офлайн-режиме лампа не шлёт и не принимает meeting, не учитывается в среднем у других.

## Кнопка (для контекста топиков)

Жесты сами по MQTT не передаются. Краткая схема `refactor`:

| Жест | Действие |
|---|---|
| 1 клик | питание вкл/выкл |
| 2 клика | действие режима: цвет (LAMP), шаг Pomodoro, отправить mood |
| 3 клика | цикл LAMP → POMODORO → MOOD |
| 4 клика | вкл/выкл DND, публикация `dnd` |
| 5+ кликов | meeting/wink, публикация `meeting` |
| удержание | яркость |

## Нагрузка

20 ламп: retained `status`, `heartbeat`, `mood`, `dnd`, `pomodoro`; heartbeat раз в 8 с; meeting по кликам; keepalive 15 с. Это по-прежнему единицы сообщений в секунду, брокеру хватит самого дешёвого VPS.

## Решение для прошивки

ACL брокера в `infra/broker/` ограничивает пользователя группы топиком `lamp/<group>/#`:

- `add-user.sh` пишет `topic readwrite lamp/${group}/#`;
- то же зафиксировано в `acl.example` и в README брокера.

Текущий `refactor` публикует и подписывается на `<group>/<local>/…` **без** префикса `lamp/`. Плановый префикс `GWL/` из `FEATURES.md` / `plans/PLAN_06_MQTT_INFRA.md` в коде тоже не используется (`MQTT_HEADER "GWL:"` объявлен и нигде не читается). В MQTT 3.1.1 брокер молча отбросит такие публикации, и лампы в группе друг друга не увидят.

**Одно исправление:** добавить префикс `lamp/` в прошивке и оставить ACL как есть. Нужно поменять:

1. Базу публикации: `lamp/` + `group` + `/` + `id` + `/`.
2. Подписку: `lamp/<group>/+/#`.
3. Разбор входящего топика. Сейчас callback берёт отправителя между первым и последним `/`. Для `lamp/<group>/<id>/<subtopic>` это даст `group/id` вместо `id` — парсер нужно сдвинуть на сегмент `lamp/`.
4. Client id `lamp-<id>`, Last Will и публикации `status` (`online` / `away` / `offline`) как в разделе выше.

Менять ACL на `<group>/#` не нужно: скрипты брокера, изоляция групп и уже выданные права останутся совместимыми с префиксом `lamp/`.
