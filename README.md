# WebLamp

Умная командная лампа на ESP8266 D1 Mini с кольцом из 24 адресных LED, одной кнопкой, web-интерфейсом и MQTT-синхронизацией между лампами группы.

Текущая реализация следует упрощенной модели: три основных режима переключаются по кругу, а DND и wink/meeting работают как быстрые действия поверх любого режима.

## Возможности

- 24 NeoPixel LED на D1 / GPIO5.
- Одна кнопка на D5 / GPIO14.
- Web-интерфейс на SettingsGyver.
- Настройки в LittleFS / GyverDB.
- WiFi-настройка через AP `WebLamp` с captive portal. Без роутера лампа работает локально.
- MQTT-группа ламп: `status`, `heartbeat`, `mood`, `dnd`, `meeting`, `pomodoro`.
- Офлайн-режим (`away`): локальные режимы живы, в среднее группы лампа не входит.
- Единая глобальная яркость для всех режимов, с ограничением тока ленты 5 В / 800 мА.
- OTA (`ArduinoOTA`), чтобы обновлять лампу в закрытом корпусе.

## Режимы

В обычном цикле переключения участвуют три режима:

| # | Режим | Назначение |
|---|---|---|
| 0 | `LAMP` | Обычная лампа: питание, яркость, цвет |
| 1 | `POMODORO` | Таймер фокус-сессий и перерывов |
| 2 | `MOOD` | Личное и командное настроение |

Отдельный режим:

| # | Режим | Назначение |
|---|---|---|
| 3 | `DND` | Не беспокоить: красное дыхание и MQTT-сигнал занятости |

DND не входит в обычный цикл `3 клика`. Он включается и выключается отдельным жестом `4 клика`, чтобы быстро уйти в "не беспокоить" из любого места и вернуться обратно.

## Кнопка

Общие жесты:

| Жест | Действие |
|---|---|
| `1 клик` | Глобальное вкл/выкл питания во всех режимах |
| `2 клика` | Действие текущего режима |
| `3 клика` | Следующий основной режим: `LAMP -> POMODORO -> MOOD -> LAMP` |
| `4 клика` | Вкл/выкл DND с возвратом в предыдущий основной режим |
| `5+ кликов` | Wink/meeting: локальная вспышка и MQTT-сигнал группе |
| Удержание | Глобальная яркость, направление меняется после отпускания |

### LAMP

| Жест | Действие |
|---|---|
| `1 клик` | Вкл/выкл питания |
| `2 клика` | Следующий цвет, шаг +32 по HSV |
| Удержание | Глобальная яркость |

Рендер плавно подтягивает текущий цвет к целевому, поэтому включение, выключение и смена цвета выглядят мягко.

### POMODORO

| Жест | Действие |
|---|---|
| `1 клик` | Вкл/выкл питания |
| `2 клика` | Управление сессией Pomodoro |
| Удержание | Глобальная яркость |

Состояния Pomodoro:

| Состояние | Что происходит |
|---|---|
| `IDLE` | Фоновый цвет, таймер не запущен |
| `WORK` | Кольцо заполняется цветом работы |
| `BREAK_SHORT` | Короткий перерыв, кольцо заполняется цветом перерыва |
| `BREAK_LONG` | Длинный перерыв после заданного количества рабочих интервалов |
| `PAUSED` | Прогресс заморожен и мигает |
| `DONE` | Интервал завершен, кольцо мигает белым |
| `CONFIRMED` | Ожидание следующего интервала, пульсирует секция Pomodoro |

Логика `2 клика`:

- из `IDLE` стартует рабочий интервал;
- из `WORK` / `BREAK_SHORT` / `BREAK_LONG` ставит паузу;
- из `PAUSED` продолжает с того же места;
- из `DONE` / `CONFIRMED` запускает следующий интервал.

В web-интерфейсе есть кнопки действия и пропуска, а также настройки длительности работы, короткого и длинного перерыва, количества помодоро до длинного перерыва, цвета работы, цвета перерыва и фонового цвета.

Во время рабочего интервала лампа публикует `pomodoro = "work:<color>"` и `dnd = "1"`. Во время перерыва и после завершения публикует `dnd = "0"`.

### MOOD

| Жест | Действие |
|---|---|
| `1 клик` | Вкл/выкл питания |
| `2 клика` | Отправить текущее настроение по MQTT |
| Удержание | Глобальная яркость |

Настроение задается в web-интерфейсе слайдером `0..120`, где `0` ближе к красному, а `120` ближе к зеленому. Режим показывает среднее значение: локальное настроение плюс онлайн-лампы группы, от которых получены MQTT-сообщения.

### DND

| Жест | Действие |
|---|---|
| `1 клик` | Вкл/выкл питания |
| `4 клика` | Выйти из DND и вернуться в предыдущий основной режим |
| Удержание | Глобальная яркость |

DND показывает медленное красное дыхание. При включении публикует MQTT `dnd = "1"`, при выключении `dnd = "0"`, если лампа онлайн и не находится в офлайн-режиме.

### Wink / Meeting

`5+ кликов` из любого режима вызывает быстрый wink/meeting:

- лампа локально делает мягкую вспышку текущим цветом;
- если MQTT доступен, публикуется `meeting`;
- другие лампы группы при получении сигнала тоже делают вспышку, если включена настройка приема wink-сигналов.

Это не отдельный режим в текущей реализации, а быстрое действие поверх активного режима.

## Web-интерфейс

Открывается по адресу:

```text
http://<IP-адрес лампы>/
```

При первом запуске или при входе в AP-режим лампа поднимает точку доступа `WebLamp`.

В web-интерфейсе сейчас есть:

- табы основных режимов `LAMP`, `POMODORO`, `MOOD`;
- экран DND, когда DND активен;
- настройки питания, яркости и цвета для LAMP;
- управление и настройки Pomodoro;
- слайдер настроения для MOOD;
- WiFi-настройки;
- MQTT-настройки: host, port, group, login, password и ID лампы (chip id, только показ);
- офлайн-режим;
- настройка приема wink-сигналов;
- строка MQTT-статуса и список видимых ламп группы.

## WiFi и старт

При старте:

1. Лампа показывает зеленую стартовую индикацию.
2. В течение короткого окна можно нажать кнопку, чтобы уйти в AP-режим.
3. Если есть сохраненный SSID, лампа пытается подключиться к WiFi.
4. Во время подключения используется мягкая зеленая индикация.
5. При успехе показывается мягкое зеленое подтверждение.
6. При ошибке или ручном входе на пару секунд включается синяя индикация AP, затем лампа сразу работает локально.
7. После завершения старта восстанавливается сохраненное состояние лампы.

Имя AP формируется как `WebLamp` или `WebLamp <последний IP>`, если ранее был сохранен IP.

## Работа без роутера

Если сохранённой сети нет или роутер не ответил, лампа не остаётся в стартовой анимации.

1. На старте около 2 секунд зелёное дыхание. Клик в этом окне поднимает точку доступа и не пытается подключиться к роутеру, пока на странице не нажать «Подключиться».
2. Иначе лампа до 15 секунд пробует сохранённый SSID (зелёное дыхание, кнопка по-прежнему читается). Точка `WebLamp` уже поднята в это время.
3. Дальше кольцо переходит в обычный режим. Кнопка, лента и web-страница работают без IP роутера.
4. Точка доступа остаётся, captive portal открывает страницу настройки. Имя точки: `WebLamp` или `WebLamp <последний IP>`.
5. Пока Wi-Fi нет, попытка STA повторяется сама: раз в 30 секунд, а если к точке кто-то подключён — раз в 2 минуты и без перезапуска AP, чтобы не сбросить телефон.
6. Когда роутер ответил и включено «Скрыть AP», точка гаснет, если к ней никто не подключён.

MQTT при недоступном брокере не блокирует `loop`: DNS и TCP идут в фоне, пауза между попытками растёт от 2 до 30 секунд. Пока набирается серия кликов, рукопожатие MQTT откладывается.

## MQTT

Полный договор payload — [`docs/protocol.md`](docs/protocol.md). Брокер и ACL — [`infra/broker/README.md`](infra/broker/README.md): пользователь группы пишет только в `lamp/<group>/#`.

По умолчанию:

- host: `broker.hivemq.com`;
- port: `1883`;
- group: `office`;
- логин и пароль брокера пустые (анонимно, пока их не задать на странице);
- id лампы: 6 hex-символов `ESP.getChipId()`, например `a1b2c3`. В портале поле «Имя лампы» остаётся, но в путь топика не входит: оно уходит только payload `meeting`.

Client id: `lamp-<id>`, clean session, keepalive 15 с. Last Will: `lamp/<group>/<id>/status` = `offline`, retained, QoS 1.

Лампа подписывается на:

```text
lamp/<group>/+/#
```

Свои сообщения отбрасывает. Путь из четырёх сегментов разбирается так: отправитель — сегмент между группой и subtopic, не текст между первым и последним `/`.

| Топик | Retained | QoS | Payload |
|---|---|---|---|
| `lamp/<group>/<id>/status` | да | 1 | `online`, `away` или `offline` |
| `lamp/<group>/<id>/heartbeat` | да | 0 | `0` или `1` (PIR), каждые 8 с |
| `lamp/<group>/<id>/mood` | да | 0 | число `0`…`120` (0 красный, 120 зелёный) |
| `lamp/<group>/<id>/dnd` | да | 0 | `0` или `1` |
| `lamp/<group>/<id>/pomodoro` | да | 0 | `work:<color>`, `break` или `idle` |
| `lamp/<group>/<id>/meeting` | нет | 0 | имя лампы из портала (wink) |

`color` в `work:<color>` — оттенок FastLED 0–255 десятичной строкой, например `work:0`.

Присутствие для среднего настроения: коллега входит в среднее только при `status=online`. Пока `status` ещё не приходил, запасной признак — heartbeat моложе 18 секунд. `away` и `offline` в среднее не входят. Своя лампа входит всегда. Усредняется число 0–120, не оттенок по кругу.

Сразу после подключения лампа публикует `status=online`. В офлайн-режиме публикует `status=away`, затем штатно отключается, чтобы Last Will не затёр `away` словом `offline`. Если пропали Wi-Fi или питание, DISCONNECT не отправляется: брокер сам публикует LWT `offline` примерно через 1,5 keepalive.

Пустая группа или пустой хост — MQTT не стартует, локальные режимы работают.

## Железо и корпус

Пины прошивки совпадают с [`hardware/power.md`](hardware/power.md). Корпус — [`mech/`](mech/).

| Функция | GPIO | D1 mini | Примечание |
|---|---|---|---|
| Данные WS2812 | 5 | D1 | 330 Ом последовательно у первого светодиода |
| Кнопка | 14 | D5 | `BTN_LEVEL 1`: кнопка на 3V3, внешний 10 кОм на GND |
| PIR | 12 | D6 | `USE_PIR 0` по умолчанию |

Лента питается от 5 В, не от 3V3 платы. Оценка тока в прошивке: около 60 мА на светодиод при полном белом, пропорционально сумме RGB. Если кадр просит больше 800 мА, яркость этого кадра уменьшается. На обычной яркости (по умолчанию 20 из 100) лимит не заметен. Это тот же потолок 5 В / 800 мА, что описан в `hardware/power.md`; у NeoPixelBus нет `setMaxPowerInVoltsAndMilliamps`, поэтому ограничение считается в `led_driver`.

## Сборка и прошивка

Первый раз плату прошивают кабелем, пока корпус не закрыт: micro-USB D1 mini после сборки снаружи недоступен. Дальше обновление по Wi-Fi. Снять крышку дна и прошить кабелем можно, но это уже разборка.

По кабелю:

```bash
pio run -e d1_mini -t upload
pio device monitor -b 115200
```

По Wi-Fi, пароль OTA `companylamp`, имя лампы `companyLamp-<id>.local`:

```bash
pio run -e d1_mini_ota -t upload --upload-port companyLamp-a1b2c3.local
```

В `platformio.ini` у env `d1_mini_ota` по умолчанию стоит `upload_port = companylamp.local` — для одной лампы на столе его меняют на имя или IP этой лампы. Пароль задаётся флагом `-DLAMP_OTA_PASS=\"companylamp\"` и `--auth=companylamp`. Пустой пароль прошивка не соберёт.

Только компиляция:

```bash
pio run -e d1_mini
pio run -e d1_mini_ota
```

Текущая среда:

```ini
[env:d1_mini]
platform = espressif8266
board = d1_mini
framework = arduino
build_type = debug
```

`build_type` оставлен `debug`, как в ветке `refactor`.

Юнит-тесты `test/test_group_logic` удалены: они проверяли старый `include/group_logic.h` (настроение 0–100, топики `state`/`wink`). Этой логики в прошивке больше нет.

## Smoke-checklist

1. Сборка: `pio run` завершается успешно.
2. Boot без WiFi: AP `WebLamp` и captive portal, кнопка и режимы работают локально, loop не замирает.
3. Boot с WiFi: зеленая индикация подключения, затем восстановление состояния.
4. `1 клик` в `LAMP`, `POMODORO`, `MOOD`, `DND`: одинаково переключает питание.
5. `2 клика` в `LAMP`: цвет меняется.
6. `2 клика` в `POMODORO`: старт, пауза, продолжение и переход к следующему интервалу работают по состояниям.
7. `2 клика` в `MOOD`: при онлайн MQTT публикуется mood.
8. `3 клика`: цикл `LAMP -> POMODORO -> MOOD -> LAMP`.
9. `4 клика`: вход в DND и выход обратно.
10. `5+ кликов`: локальная wink-вспышка и MQTT meeting publish при онлайн.
11. Web tabs переключают основные режимы, а DND-переключатель ведет в DND-экран.
12. Офлайн-режим отключает MQTT-активность, локальные режимы продолжают работать.
